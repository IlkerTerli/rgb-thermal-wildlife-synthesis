# pix2pix Experiments

This directory documents the pix2pix experiments used for paired
RGB-to-thermal image translation.

The experiments were conducted as part of a bachelor thesis investigating
synthetic and generative approaches for RGB-to-thermal image translation and
wildlife-scene generation.

## Translation Direction

The domain convention used throughout the pix2pix experiments is:

- Domain A: RGB images
- Domain B: Thermal images
- Translation direction: A -> B

Unlike CycleGAN, pix2pix requires spatially corresponding paired images during
training.

## Experiment Overview

Five relevant training runs were conducted:

| Experiment | Dataset | Epochs | Batch size |
|---|---|---:|---:|
| Small | FLIR Small | 20 | 1 |
| Medium 20 | FLIR Medium | 20 | 8 |
| Medium 100 | FLIR Medium | 100 | 8 |
| Large 20 | FLIR Large | 20 | 8 |
| Large 100 | FLIR Large | 100 | 8 |

The experimental design therefore allowed the influence of both dataset size
and training duration to be investigated.

## Common Training Configuration

The following central parameters were shared by the documented pix2pix
experiments:

| Parameter | Value |
|---|---|
| Model | pix2pix |
| Dataset mode | aligned |
| Direction | A -> B |
| Learning rate | 0.0002 |
| Generator | U-Net 256 (`unet_256`) |
| Discriminator | basic |
| Input channels | 3 |
| Output channels | 3 |
| L1 loss weight | 100.0 |
| Load size | 286 |
| Crop size | 256 |
| Preprocessing | `resize_and_crop` |
| Epoch decay | 0 |

The main experimental differences were dataset size, training duration, and the
batch size used for the Small configuration.

## Experiment Files

Each experiment directory contains the original training-loss log and the
configuration files generated by the training framework.

Typical files include:

```text
loss_log.txt
pix2pix_train_opt.txt
pix2pix_test_opt.txt
train_opt.txt
test_opt.txt
```

The exact filenames depend on the corresponding archived run.

- `loss_log.txt` contains the recorded training-loss output.
- `pix2pix_train_opt.txt` or `train_opt.txt` contains the original training
  configuration.
- `pix2pix_test_opt.txt` or `test_opt.txt` contains the original inference/test
  configuration.

### Medium 20-Epoch Run

The `medium_20ep` directory additionally contains both:

```text
train_opt.txt
pix2pix_train_opt.txt
```

The files originate from different training invocations.

The relevant difference observed during repository reconstruction is the
recorded phase setting:

```text
train_opt.txt:
phase: train

pix2pix_train_opt.txt:
phase: pix2pix_train
```

Both files are retained as archived experiment metadata rather than being
retrospectively modified.

## Dataset Preparation

The reusable pix2pix dataset-preparation workflow is implemented in:

```text
src/data_preparation/prepare_pix2pix_dataset.py
```

Its command-line interface can be inspected with:

```bash
python src/data_preparation/prepare_pix2pix_dataset.py --help
```

The preparation workflow combines corresponding RGB and thermal images into
the side-by-side representation expected by the pix2pix framework:

```text
[ RGB image | Thermal image ]
```

The RGB half forms domain A and the thermal half forms domain B.

## Quantitative Evaluation

Because pix2pix uses paired and spatially corresponding images, the generated
thermal-like output (`fake_B`) can be compared directly with the corresponding
real thermal target (`real_B`).

The reusable quantitative evaluation implementation is located at:

```text
src/evaluation/evaluate_pix2pix_metrics.py
```

The evaluation calculates:

- PSNR
- SSIM

Archived summary results are stored in:

```text
results/tables/pix2pix/
```

Further details about the quantitative results are available in:

```text
results/tables/pix2pix/README.md
```

## Archived Experiment Metadata

The files in the experiment directories preserve the settings and logs of the
original training and test runs.

Some files may contain machine-specific local paths from the original
experimental environment. These values are intentionally preserved as
experiment metadata and are not required by the reusable source-code
implementations.
